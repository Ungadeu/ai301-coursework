# pr-precheck: rubric-driven PR grading



## The question

Is this pull request ready to be reviewed by a human maintainer?

You evaluate a "PR package," which is a collection of artifacts proving the repair is complete and safe. You read the implementation blueprint (plan.md), the draft announcement (pr_draft.md), the proof of functionality (test_evidence.md), and the actual code changes (diff) to ensure they perfectly align with the original issue and the repository's rules.


## Inputs and modes

Live mode: Grades the user's local branch before they open a PR. You will read the local plan.md (including its deviations), the pr_draft.md (title and description) files, the test_evidence.md file, the git diff main...HEAD, and fetch the target issue thread and repository conventions (e.g., CONTRIBUTING.md and the PR template). The branch's diff is gathered concretely by running git diff main...HEAD from the working copy to see everything changed relative to the default branch. For example, when checking the newline prompt injection fix for issue #64, this command reveals the exact lines altered in safety/prompt_defense.py and the added tests in tests/unit/test_prompt_defense.py. (If evaluating a house-chain student, you read their provided house issue, repro pack, and branch).   

Eval mode: Grades a practice package. The bundle markdown file provides all evidence (issue, thread, repo-facts, plan, PR description, test evidence, and diff). Do not fetch external data in eval mode—the bundle is a closed book. Every check runs with the full verdict rule.

## The scope seam (live mode only)

In live mode, always read scope.md before starting. It acts as the track map. If the issue URL does not belong to the repo listed in scope.md, refuse to run. If the Repo: line in the scope is an unfilled placeholder (like <ORG>/<PATH-REVIEW-REPO>), refuse to run and tell the user to configure their scope. Apply any house rules found in scope.md to your grading. In eval mode, ignore scope.md entirely.


## The voice seam (live mode only)

In live mode, read voice-guide.md to understand the required tone and formatting. This guide gates the outgoing text found in the PR title and description (pr_draft.md). If the draft breaks a rule, report the broken rule in the output summary. However, a voice guide violation never changes the final accept/reject verdict on its own. In eval mode, ignore the voice guide entirely.


## Component reads

Read CONTRACT.md (for the unchangeable output structure), rubric.md (for the required checks and verdict rule), procedure.md (for the grading steps), and references/evidence-guide.md (for where to find evidence).

Execute the steps exactly as written in procedure.md. Compare the diff against the plan to catch silent drift, verify test evidence against the original issue, ensure no debugging debris is present in the code, and check the description against the repo's PR template and AI policies. If procedure.md is silent on how to perform a step, report the gap to the user and never improvise around it. Refuse to run if any required input file (plan.md, pr_draft.md, test_evidence.md) is missing or empty, or if rubric.md or procedure.md contain no content.


## Verdict and output

The verdict space is strictly binary: accept (the PR is ready to submit) or reject (the PR must be held for fixes). Output the exact JSON block format dictated in CONTRACT.md. End your reply with this fenced JSON block, valid and last, with absolutely nothing written after it.


```json
{
  "item": "<PR URL or bundle id>",
  "checks": [
    {"name": "<check name>", "grade": "pass|fail|unclear",
     "evidence": "<one line: the fact or quote that decided it>"}
  ],
  "verdict": "accept|reject"
}
```

## Grading discipline

You must grade under these strict standing rules:Evidence first: Grade each check from the rubric as pass, fail, or unclear with a one-line citation. Never grade without a factual quote. 
Grade the thing, not the polish: Evaluate the concrete evidence present, not how eloquently it is written.The rubric decides: You do not use personal judgment. If the evidence meets the rubric's condition, it passes.The procedure decides how: You follow the steps in procedure.md without skipping or inventing new checks.Unclear means fail: If the rubric's verdict rule is silent on how to treat an unclear grade, you must treat it as a fail.
