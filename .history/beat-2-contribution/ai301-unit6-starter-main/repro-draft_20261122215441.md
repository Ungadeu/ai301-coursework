## Reproduction: Undefined Custom Curve Outputs Zero

Reproduced on `main`: an input that references a never-defined custom curve outputs a flat 0 instead of following the stick.

### Environment

- EdgeTX `main` at `8d79d2659` (2026-11-20), radio firmware code built for TX16S (`-DPCB=X10 -DPCBREV=TX16S`), Debug
- macOS 26.6.2 (x86_64), Apple clang 21.0.0, cmake 4.4.5
- Difference from the issue: I ran the radio firmware's mixer through the repo's own unit-test harness (`gtests-radio`), not on a physical radio or the GUI simulator.

**Steps**

1. Clone with submodules and add this test as `radio/src/tests/repro_1067.cpp` (the `tests/` CMake globs `*.cpp`, so it's picked up automatically):

```cpp
#include "gtests.h"
#include "hal/adc_driver.h"
#include <iostream>

// Same definitions as radio/src/tests/mixer.cpp
class Repro1067Test : public EdgeTxTest {};
#define THR_CHAN  inputMappingGetThrottle()
#define THR_STICK THR_CHAN

TEST_F(Repro1067Test, UndefinedCurveIsFlatZero)
{
  g_eeGeneral.stickMode = 1;  // mode 2
  const int stick = inputMappingConvertMode(THR_STICK);
  const int positions[] = {-1024, 0, +1024};

  std::cout << "[repro-1067] isCurveUsed(0) [CV1] = " << isCurveUsed(0) << "\n";

  // Control: default throttle input, no curve.
  for (int pos : positions) {
    anaSetFiltered(stick, pos);
    evalMixes(1);
    std::cout << "[repro-1067] no curve      stick=" << pos
              << " -> THR channel=" << channelOutputs[THR_CHAN] << "\n";
  }

  // Trigger: apply never-defined custom curve CV1 to the throttle input.
  ExpoData *expo = expoAddress(THR_STICK);
  expo->curve.type = CURVE_REF_CUSTOM;
  expo->curve.value = makeSourceNumVal(1);
  for (int pos : positions) {
    anaSetFiltered(stick, pos);
    evalMixes(1);
    std::cout << "[repro-1067] CV1 undefined stick=" << pos
              << " -> THR channel=" << channelOutputs[THR_CHAN] << "\n";
    EXPECT_EQ(channelOutputs[THR_CHAN], 0);  // issue's behavior: Y = 0
  }
}
```

1. Build and run it (same targets CI uses in `tools/commit-tests.sh`):

```
mkdir -p build/repro && cd build/repro
cmake -G Ninja -DPCB=X10 -DPCBREV=TX16S -DCMAKE_BUILD_TYPE=Debug -DDISABLE_COMPANION=YES ../..
cmake --build . --target native-configure
cmake --build native --target gtests-radio
native/gtests-radio --gtest_filter='Repro1067Test.*'
```

**Local build notes (my machine only, not EdgeTX issues):** my Command Line Tools install is missing libc++ headers, so I built with a wrapper that adds `-stdlib++-isystem <SDK>/usr/include/c++/v1`, pointed `-DPython3_EXECUTABLE` at a venv with the `pyproject.toml` deps, built SDL2 2.32.10 from source (`-DSDL2_DIR`), and generated the `hal_*`/`datacopy` targets before `gtests-radio`.
